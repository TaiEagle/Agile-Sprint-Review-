# Agile-Sprint-Review-
To interpret user needs and implement them into a program, there are several steps that need to be completed. First determine what the user wants to do then create a user story with the details. Then the user story is added to a product backlog to then be added to a sprint, where the developers create code to satisfy the requirements of the user story. After it is developed it is tested, then released at the end of the sprint. User sotries helps with this process by taking what the user wants and conveying that in an effective and concise method to the developers and testers.
I approach developing programs by determining the Definition of Done, and recursivly breaking down each feature into smaller features to solve one small problem at a time, these small problems will add up to completing all of the features. I hope to include daily sprints in my future development, because it increases team collaboration and effectiveness. 
To be a good team member in an agile team is all about collaboration, and ensuring every person on the team is continously moving forward and if a teamate hits an impasse, it is necessary to help them solve what ever problem they are facing so they can move forward.
